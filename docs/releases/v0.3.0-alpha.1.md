# Network controls and transport evaluation preview

This prerelease bundles the first five delivery-queue slices: directional delay/loss,
a plain TCP baseline, offline regression gates, scheduled outage recovery, and an
independent Rust adapter starter with conformance checks. Download a native x86-64
or ARM64 GNU/Linux archive and `SHA256SUMS`, verify it, then follow the
[transport quickstart](https://github.com/0xprames/natbench/blob/main/docs/TRANSPORT_QUICKSTART.md).

The controller and four separately built example executables are included. Matched
comparisons, gates, recovery and the bundled starter checker need no Rust build.
Fixture experiments require Linux/root and the documented kernel/system tools.

```sh
sudo ./natbench doctor --probe
sudo ./natbench compare examples/transports/direct.json --runs 3 --capture --artifacts ./comparison-001
sudo chown -R "$(id -u):$(id -g)" comparison-001
./natbench assess comparison-001/report.json --policy examples/transports/regression-policy.json --artifacts ./assessment-001
sudo scripts/check-transport-recovery.sh ./natbench ./bin/natbench-transport-recovery ./recovery-001
sudo ./natbench conform examples/adapter-starter/adapter.json --capture --artifacts ./starter-001
```

- **Declared conditions:** comparison input 2 applies matched upload/download delay
  and random loss. Application inputs 4/5 expose named links and scheduled changes,
  with initial/current/final kernel state, drop counters and partial/cancel evidence.
- **Three real baselines:** iroh, Quinn and plain TCP verify the same fresh
  application messages and bulk payloads. TCP records kernel/congestion/socket and
  no-TLS/no-authentication semantics; blocked UDP succeeds on TCP and fails on
  direct QUIC. Compatible workloads do not imply equal security/framing overhead.
- **Saved regression checks:** `assess` validates all comparison cohorts against
  explicit delivery, p95 RTT, verified goodput and sample requirements. Relative
  baseline policies require matched metadata with explicit build-version allowances.
  It runs offline without root and retains inputs, coverage and JSON/JUnit.
- **Fresh recovery evidence:** nine real directional/bidirectional outage cases
  verify new message and bulk sequences after restoration on the original connection.
  Three persistent outages fail with phase/deadline and no recovery metric.
  Restoration-to-delivery includes marker handling, retransmission and scheduling.
- **Independent adapters:** `new-adapter.sh` copies a standalone Rust project with
  vendored protocol, locked dependencies, replaceable TCP backend and pinned CI.
  `conform` checks one adapter's bounds and expected total-loss behavior. Unsupported,
  invalid and incomplete claims stay nonpassing; the adapter must honestly verify bytes.

Native archive CI exercises the packaged executables without Rust on PATH and
rebuilds included source/generated adapters. Older inputs retain their semantics;
new input/evidence kinds are documented in the included `schemas/` directory.
Application logs, timelines and optional bounded packet captures remain available.

This is an evaluation checkpoint, not completion of M3. Fixed IPv4/Linux roles,
three kernel NAT profiles and separately defined direct/iroh-connectivity experiments
remain the scope. Jitter/rate/MTU controls, relay restart, NAT rebinding/reconnecting
policies, nested/dual-stack networks and broader WebRTC/libp2p/TURN coverage remain
later work. Synthetic successes and conditional timings do not establish production
connectivity or performance. Stable v0.2.0 still awaits outside evaluation and
resolution of blocking findings; this prerelease does not satisfy that gate.
